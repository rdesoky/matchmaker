# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm ci` — install dependencies on a fresh checkout; `sass`, `esbuild`, `chokidar` and `livereload` are required for builds, tests and the dev server.
- `npm start` — build `dist/`, serve it at `http://127.0.0.1:8080` (next free port if busy), and rebuild/reload on changes under `v2/`, `v3/`, `shared/`, `images/`, `index.html` or `404.html`. Check UI changes in both shells: `/` (v3) and `/v2/` (v2).
- `npm test` — unit tests plus a full build/validate smoke test; run before finishing.
- `node --test --test-name-pattern='decodeEntities' tests/run.js` — run only matching named tests (Node 24 in CI).
- `npm run build`, `npm run build:staging`, `npm run build:prod` — write `dist/` with the dev/staging/prod API base and CNAME rules defined in `tools/build.js`.
- `npm run check` — validate an existing `dist/` (secrets, forbidden files, CNAME/base rules, string keys, local links, JS syntax, Sass output). There is no lint script; this is the validation gate.
- `npm run serve` — serve `dist/` with a same-origin `/cgi-bin/` proxy (`KOBOOL_API_TARGET` overrides the API host) but no file watching.
- For a GitHub Pages project-site preview under a subpath: `node tools/build.js --env=staging --base=/<repo> --no-cname`, then `node tools/validate.js --env=staging --base=/<repo>`. Domain-root deployments use no `--base` and keep the generated CNAME.

## Architecture

- This is a static frontend for a CGI API, not a server-rendered app. `dist/` is generated by `tools/build.js` and is never edited or committed; sources are `index.html`, `404.html`, `v2/`, `v3/`, `shared/`, `images/`, plus the `tools/` build scripts and `tests/run.js`.
- There are two live shells. The root `index.html` loads `v3/init.js`, which configures RequireJS from `v3/modules/`, maps `CssLinks`/`PgLinks` to `v3/` assets, and starts the `app` module. `v2/index.html` is the legacy shell, backed by `v2/init_vars.js` manifests and mostly global scripts. Shared runtime code lives in `shared/`; a UI change normally has to be checked in both shells. New v3 modules must be added to the hardcoded `MODULES` list in `v3/init.js`; a new v2 page generally needs entries in both `v2/init_vars.js` (`PgLinks`, often `JSLinks`) and the `Packages` table in `v2/init.js`.
- Both shells navigate by hash (`#pg=...`) and fetch page fragments from `PgLinks` at runtime. Because injection happens after DOMContentLoaded, the loader must explicitly call `KStrings.bind(root)` on the new markup; v3 page modules also expose `requireCSS`/`requireStrings`/`onload`/`onchange`/`ondestroy`/`postRender` hooks.
- `shared/config.js` sets `APP_CONFIG.apiBase`; the build replaces it per environment (dev uses same-origin `/cgi-bin/`, staging/prod call `//api.kobool.com/cgi-bin/`). Localhost previews force the base back to `/cgi-bin/`, where `tools/serve.js` proxies it. v3's `v3/modules/http.js` derives all API URLs from that base once at module creation and sends `sid` as a header; v2 uses the `Http.cgiBase`/`gCGI` globals. Hardcoded `src="/cgi-bin/kpic.pl?..."` URLs in page fragments are rewritten at build time, but the profile-picture upload form stays same-origin because its iframe response calls `window.parent.UpdatePics`.
- Page copy is authored as XML under `v2/text/` and `v3/text/` and compiled to JSON. `shared/strings.js` (`KStrings`) resolves `?lang=` → `lang` cookie → navigator → default, sets `<html lang/dir>` (Arabic → RTL), and exposes `RS`, `RAS`, `_S`, `_PS`, `_HS`. It binds attributes such as `data-string`, `data-string-attr`, `data-string-template`, `data-visible-if` (`member|guest` or `ar|en`) and `data-options` (unsuffixed `/shared/data/<name>.json`, with `data-options-group` selecting `data.sfilters[group]`). `data-visible-if` is distinct from k-template's `data-show-if`, which evaluates a `(? ... ?)` expression. Repeated markup uses `data-fragment="/v2/pages/..."`; the build inlines fragments, including nested ones, and fails on missing files or cycles.
- Theme is applied pre-paint by `shared/theme.js`: saved `kobool-theme` mode (`dark|light|system`) plus OS preference set `html[data-theme]`/`[data-theme-mode]`, with `window.KTheme` and `themechange` events. Session truth is the `sid` cookie plus the global `SSN` object; both shells watch the cookie for `SSNUpdate` with a 15-minute activity timeout.
- Stylesheets are authored as `.scss` and compiled to the `.css` paths the HTML links (for example `v3/css/base.scss` → `/v3/css/base.css`). `_`-prefixed partials are Sass-only. `shared/theme.scss` nests dark overrides under `html[data-theme="dark"]`; `v3/css/font-awesome.css` is vendor CSS copied verbatim. Sass and minified JS/CSS get source maps with embedded source content.
- `tools/build.js` copies only allowed static files (blocking server scripts, secrets, raw XML and Sass), compiles Sass and XML, injects environment config, rewrites URLs/API bases, inlines fragments, minifies JS/vendor CSS, and writes CNAME unless `--no-cname`. `--source` can supply shared countries/options XML from a private repo; `compile-data.js` generates the unsuffixed JSON defaults from the Arabic files and regenerates `birth_years.json`. `npm run check` must pass before publishing; CI runs tests plus a staging build/check, and `.github/workflows/deploy.yml` publishes `dist/` to GitHub Pages.
- Analytics is disabled unless `analyticsId` is set in `shared/config.js`; the `ga()` shim then becomes a no-op.
